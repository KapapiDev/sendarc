Date: 2026-08-28

## Evidence

- Design reference: [`design/SendArc-final-reference.png`](design/SendArc-final-reference.png) — 1024 × 1536.
- Local production-build capture: [`design/SendArc-landing-qa-2026-08-28.png`](design/SendArc-landing-qa-2026-08-28.png) — full page at a 1303 × 854 browser viewport, 1303 × 4583 output.
- Source under test: `website/dist`, generated by `npm run build` and served with `astro preview`.

The controlled Chrome check found a 1303 px document width and a 1303 px viewport width, so the page had no horizontal overflow. Both SendArc logo images were complete and had non-zero intrinsic dimensions.

## Reference comparison

The implementation preserves the reference's core visual system:

- white and pale-blue surfaces with dark navy type and cobalt actions;
- a split hero with a legacy-app → SendArc → Gmail diagram;
- compact benefit blocks, numbered setup steps, a trust-oriented feature area;
- FAQ disclosure rows, a strong closing download callout, and a structured footer.

Intentional product-truth changes from the reference:

- Microsoft 365 claims were removed because the beta sends through Gmail and Google Workspace only;
- the message path states local preview and explicit Send instead of implying automatic transmission;
- the business-beta form, privacy warning, open-source/legal links, and independence notice add launch-required content;
- unsupported pricing, customer-logo, and compatibility claims were not invented.

## Result

The local production build is visually coherent with the supplied direction and has no observed desktop-width overflow or missing primary imagery. Deployment verification remains separate: repeat the same check on the generated Cloudflare Pages URL after the first successful upload.
