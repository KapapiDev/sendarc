# SendArc beta: IT evaluation notes

SendArc `0.1.0-beta` is a focused market-validation build, not an enterprise-managed product. This page helps an IT administrator evaluate a tagged beta without implying features that do not exist.

## Scope and limitations

- Gmail and Google Workspace only.
- Simple MAPI bridge, not a desktop mail client.
- One connected account per Windows user.
- No Microsoft 365 support, MSI package, fleet dashboard, group-policy templates, billing system, or support SLA.
- No silent self-updater or update Scheduled Task. Update checks only direct the user to the official GitHub release page.
- The no-payment beta may be unsigned and can be blocked by SmartScreen, AppLocker, WDAC, or organizational policy.
- Application compatibility is not assumed from the presence of an email menu; validate the exact x86/x64 application and workflow.

Treat [docs/REQUIREMENTS_MATRIX.md](docs/REQUIREMENTS_MATRIX.md) and the tagged release's CI run as the authority for what has actually been verified.

## Intended installation footprint

The rebranded installer targets these locations and identifiers:

| Purpose | Target |
|---|---|
| 64-bit program files | `%ProgramFiles%\SendArc` |
| 32-bit interceptor files | `%ProgramFiles(x86)%\SendArc` |
| Per-user queue | `%LOCALAPPDATA%\SendArc\queue` |
| Per-user settings/log | `%APPDATA%\SendArc` |
| 64-bit mail client | `HKLM\SOFTWARE\Clients\Mail\SendArc` |
| 32-bit mail client | `HKLM\SOFTWARE\WOW6432Node\Clients\Mail\SendArc` |
| Uninstall entry | Add/Remove Programs display name `SendArc` |
| Credential storage | Windows Credential Manager service `SendArc`, account `oauth-tokens` |

Machine-wide MAPI registration requires elevation. The installer is intended to preserve the prior default mail-client identity before selecting SendArc and restore it during uninstall only when doing so is safe. It must not uninstall or delete Affixa, go-mapi, Outlook, Thunderbird, or another registered client. Confirm these behaviors against the tagged beta's installer smoke results before broad deployment.

If go-mapi is already installed, do not assume side-by-side operation is safe. Evaluate the installer's explicit coexistence warning and previous-handler backup on a disposable machine before deployment.

## Network and data boundaries

The desktop application needs outbound HTTPS access to:

- Google's OAuth endpoints for installed-app sign-in and refresh;
- `gmail.googleapis.com` for `users.messages.send`;
- `api.github.com` and `github.com/kapapi-dev/sendarc/releases` for optional update metadata and manual downloads.

The OAuth loopback callback binds to an ephemeral port on `127.0.0.1`. It is not a LAN listener or a SendArc relay service. Do not create a broad inbound firewall exception; use the narrow executable/loopback rule generated by a verified installer only if the target environment requires one.

Message data is queued per user on the Windows machine and, after an explicit Send click, goes directly to Google's Gmail API. SendArc does not operate a message-content server. Tokens are stored through Windows Credential Manager. Local logs are designed to exclude recipients, subjects, bodies, attachment names, OAuth tokens, and Gmail response bodies.

## Deployment guidance for the unsigned beta

1. Obtain `SendArc-Setup-0.1.0-beta.exe` and `SHA256SUMS.txt` from the same immutable GitHub release.
2. Verify the SHA-256 checksum in a controlled staging directory.
3. Review the release's CI run, known limitations, and signing declaration.
4. Test install, first launch, x86 and x64 MAPI interception, Gmail consent/send, update notification, and uninstall/handler restoration on a disposable representative machine.
5. Approve the exact hash through the organization's normal software-control process if policy permits unsigned software.

Do not disable Microsoft Defender, SmartScreen, AppLocker, WDAC, or another security control as a workaround. If organizational policy requires a trusted publisher, wait for a properly Authenticode-signed release.

Example checksum verification:

```powershell
$installer = '.\SendArc-Setup-0.1.0-beta.exe'
$line = Get-Content .\SHA256SUMS.txt |
  Where-Object { $_ -match '\s+SendArc-Setup-0\.1\.0-beta\.exe$' }
if (-not $line) { throw 'Installer entry is missing from SHA256SUMS.txt' }
$expected = ($line -split '\s+')[0].ToLowerInvariant()
$actual = (Get-FileHash -LiteralPath $installer -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "Checksum mismatch: expected $expected, got $actual" }
"Checksum verified: $actual"
```

## Updates

SendArc's beta update path is notify-only. The app may report that a release exists and open the official release page, but it does not silently replace the EXE/DLLs or create an automatic-update Scheduled Task. An administrator should repeat the checksum, smoke, and policy review for each version.

## Removal and per-user residue

Use the normal Windows uninstall entry. The machine-wide uninstaller should remove only SendArc-owned binaries, MAPI registrations, firewall entries, and uninstall metadata, and restore the prior mail handler when safe. Per-user queue/settings and Credential Manager entries may require each user to sign out/discard pending items or remove their own data. Never use a broad cleanup command that enumerates or deletes unrelated mail clients.
